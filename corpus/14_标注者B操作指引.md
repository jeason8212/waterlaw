## 二、环境准备：一个检索命令，不需要 SQL

不需要装数据库、不需要会 SQL。只要有 Python（项目一直用它跑脚本），一条命令就能查条文：

```
cd build
python tools/lookup.py 排污口 饮用水
```

输出是排好版的中文条文，每条自动标明时点状态，例如：

```
[L-017#64-1]  水污染防治法 第64条第1款   (B0:有效 | B1:失效)
  在饮用水水源保护区内，禁止设置排污口。
```

**常用命令**：

| 想做什么 | 命令 |
|---|---|
| 找同时含两个词的条文 | `python tools/lookup.py 排污口 饮用水` |
| 找含任一关键词的条文 | `python tools/lookup.py 采砂 砂石 --any` |
| 只在某一部法里找 | `python tools/lookup.py 采砂 --doc L-003`（L-003 = 黄河保护法） |
| 看某条文全文（含同条各款） | `python tools/lookup.py --id L-001#318` |
| 看 6 部法律及各自时点效力 | `python tools/lookup.py --list` |
| 进入交互模式（逐行输关键词） | `python tools/lookup.py` |

**时点有效性不用自己算**——每次检索结果都会标 `B0:有效/失效 | B1:有效/失效`。只需记住两条：
- **水污染防治法（L-017）在 B1 已废止**——B1 侧答案不得引用；
- **生态环境法典（L-001）在 B0 尚未施行**——B0 侧答案不得引用。

## 三、逐查询操作步骤（每条查询）

### 列职责总览（哪些要填、哪些不要动）

| 列 | 你要做什么 | 说明 |
|---|---|---|
| `b0_prov_ids` / `b0_basis` / `b1_prov_ids` / `b1_basis` | **填**（组 A 行已有草稿，审核后定） | 见下方填法表 |
| `flip` | **填**（组 A 行已有草稿值，判断对错，错了直接改） | 主依据是否在两时点间迁移：`Y`＝换了（含"B0 空→B1 有"）；`N`＝没换（B0 依据到 B1 仍管用）。两侧都空 = `N` |
| `answer_type` | **填** | `empty`（该侧查无依据）/ `single`（一条主依据）/ `multi`（两条以上并列）。可只有一侧 empty，此时按整体情况填、flip 通常为 `Y`。**multi 只数"真会被引用的"条款**：法典援引/重申型附加条款（依据变厚）不把答案变成 multi，仍填 `single`——详见协议规则 2.5 |
| `verify_note` | **条件必填** | 判空（填 `(none)`）**必须**写：声明库外还有什么法可能有规定；拿不准、或排除了某个候选，也写这里；没话可写就留空 |
| `alt_candidates` | **不要动** | 系统预生成的参考线索（检索器排序＋摘要），不是要你填的空 |
| `review_action` / `review_note` | **只组 A 行填**；组 B 行留空 | `接受`／`修改`／`换选` 三选一；改动理由写 `review_note`，仲裁时全靠它还原判断 |

1. **读输入**：表单里只有类别、流域、区域、事由（如 Q01：跨省界／长江／湖北—湖南／"省界断面水质监测"）。
2. **拆关键词**：从事由提取 2–4 个检索词（如：省界、断面、水质、监测）。
3. **两侧分别检索**：先查 B0 侧答案，再查 B1 侧答案。检索时心里记住时点——B0 侧 L-017 可用，B1 侧不可用。
4. **选定 1–3 条主依据**，按编码手册规则 2 的优先序：特别法（长江法/黄河法对长江/黄河事项）＞ 规范密度更完整者 ＞ 法典接管条款；并列依据只收冗余孪生或功能互补条款。
5. **填表**（款级编号，分号分隔）：

| 列 | 填法 | 示例 |
|---|---|---|
| `b0_prov_ids` | 文号#条号-款号，多条用英文分号 `;`；无依据填 `(none)` | `L-017#64-1` 或 `L-017#64-1;L-004#34-1` |
| `b0_basis` | 一句话说明为什么是它（引用条文中关键短语） | 水污染防治法第64条：禁止在饮用水水源保护区设置排污口 |
| `b1_prov_ids` / `b1_basis` | 同上 | `L-001#318-1;L-004#34-1` |
| `flip` | 主依据迁移或 B0 空→B1 有 = `Y`；主依据不变且 B0 依据仍被 B1 覆盖 = `N` | `Y` |
| `answer_type` | `empty`（两侧均无）/ `single` / `multi` | `single` |
| `verify_note` | 判空的**必须**声明语料边界；有疑问也写这里 | （none，库外湿地保护法第28条或有规定，本库无依据） |

## 三之二、预标注组（组 A）怎么审

用 `15_预标注表单_待审核.csv` 时，先看 `group` 列：

- **组 B（空白）**：按上面第三节从零标注，和全空白方案完全一样。
- **组 A（预标注）**：答案列里已有别人的草稿，你的任务是**审核**，不是重标。每条 3–5 分钟：

  1. 读 `b0_prov_ids` / `b1_prov_ids` 里的草稿，用 `python tools\lookup.py --id 编号` 看条文原文；
  2. 看 `alt_candidates` 列——那是检索器给的其他候选（带分数和条文摘要），里面可能有比草稿更贴切的条款；
  3. 在 `review_action` 列填三选一：

| review_action | 什么时候填 | 还要做什么 |
|---|---|---|
| `接受` | 草稿正确 | 不用改任何答案列 |
| `修改` | 草稿方向对但要调整（如补一条并列依据、改 flip 判定） | 直接改对应答案列，并在 `review_note` 写一句为什么 |
| `换选` | `alt_candidates` 里有更合适的条款 | 用它替换答案列，`review_note` 写明理由 |

  4. 如果草稿和 alt 候选都不对，自己用 `lookup.py` 检索出别的条款填进去，`review_action` 填 `换选` 并在 `review_note` 写"自行检索所得"。

**`alt_candidates` 列怎么读**：格式是 `B0 其他候选：编号(分数) 摘要；… ｜ B1 其他候选：…`。三个要点：

- 它是**检索器的排序结果**，不是"相关条款全集"——分数低的不代表不重要，分数高的也不代表更贴切（实测噪声条款常排在专门条款前面）。它只是提示"还有这些条款存在"。
- 分数**不是人工判断**：由固定公式（IDF 加权词重合度 × 位阶 × 规则调整）自动算出，度量的是**字面词汇重合**而非法律相关性。例：Q01 里"监测井防渗"条款(0.24)排在"省界水体监测"专条(0.17)前面——共享高频词导致高分，但法律上不相关。**分数是检索器的意见，裁决靠你对照条文原文和编码手册**。
- 摘要**围绕查询词截取**（前后各一段），所以可能带省略号开头，是正常现象。
- **候选列里没有 ≠ 不该填**。你自己用 `lookup.py` 检索到的任何条款都可以填。判断依据永远是**条文原文对照编码手册规则**，不是"候选列里有没有"。

**注意**：组 A 的一致性数字在论文里只作"锚定条件"报告，组 B 才是主结果。所以**不要因为"草稿看起来合理"就一律接受**——你的独立判断恰恰是本环节最值钱的东西。实在拿不准的，按自己的判断填，把犹豫写进 `review_note`。

## 四、最容易踩的三个坑（校准例的教训）

1. **漏计**：A 的历史错误几乎全是漏——漏特别法（长江法对长江流域事项优先于法典）、漏冗余孪生（同一禁止可能在水法、旧污染防治法、法典三处逐字重复）、漏旧法既有条款（B0 判空前先全库扫一遍关键词）。**宁可多检索三轮，不要轻易判空**。
2. **flip≠N 的隐性陷阱**：B1 依据变厚（多了法典同构条款）**不算**翻转；只有主依据换了或规范实质变化才算 Y。
3. **概念替换**：法典改了用语——"风景名胜区水体"→"自然保护地水体"、"损害赔偿纠纷"→"侵害合法权益…调解处理"。条文用新词，查询用旧词，检索不到 ≠ 无依据，换关键词再查。

## 五、做完之后

1. 表单**另存为** `corpus/15_预标注表单_B完成.csv`（用空白版则存 `12_双标注表单_B完成.csv`；不要覆盖原表）；
2. 自查一遍第四节的三个坑（重点：所有 `(none)` 是否都声明了语料边界；组 A 的 `review_action` 是否都填了）；
3. 交回给协调者（研究者本人），由其运行：
   ```
   python build/tools/kappa_iaa.py --b corpus/15_预标注表单_B完成.csv
   ```
   先出一致性数字（会自动分"组 B 干净 IAA"与"组 A 锚定条件"两栏），**然后才开仲裁**——顺序不可颠倒，仲裁前的 κ 才是有效的 IAA。
4. 仲裁时你与 A 逐条核对分歧（以条文原文为唯一依据），重点先看 κ 报告里标记"优先复核"的查询。

### 保存时的三条纪律（Excel / WPS 用户必读）

1. **不要增删行、不要改 `query_id` 列**——一致性是按 `query_id` 对齐的，改一个就整行对不上。也不要调整列顺序或改列名。
2. **编码不用管**：Excel/WPS 另存 CSV 时通常转成 GBK，计算工具已自动识别 UTF-8 / GBK / UTF-16，能正常读。若另存时弹出"是否保留此格式"，选"是/CSV"即可。
3. **不要用"分列""合并单元格""自动格式"**：`b0_prov_ids` 一格里可能有多个编号用分号隔开（如 `L-017#26-1;L-004#34-1`），单元格被拆分或合并会让这一行作废。若 Excel 把 `L-017#26-1` 自动识别成日期/公式，重新输入时把该列设为"文本"格式。
